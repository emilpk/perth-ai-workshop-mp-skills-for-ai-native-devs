Which skill, and when

A skill is a written-down workflow your agent follows. Some you start yourself. Others the agent picks up on its own when the task fits.

They work in Claude Code, Codex, Copilot, Cursor and other agents. In Claude Code and Copilot, type /grill-with-docs. In Codex, type $grill-with-docs. These notes match version 1.3.

you start it type it or ask for itagent picks it runs when it fits

Tonight: building a new feature

  1. /grill-with-docsyou start it

    Interviews you about the idea, one question at a time, until there are no loose ends. Along the way it writes the project's words into GLOSSARY.md and big decisions into docs/adr/.

    No repo, just a plan or some writing? /grill-me is the same interview without the paper trail.

  2. /to-specyou start it

    Writes up what you agreed as a spec and files it in your issue tracker. No new questions, it just writes it down.

  3. /to-ticketsyou start it

    Breaks the spec into small tickets. Each one says which tickets it's waiting on.

    Do steps 1 to 3 in one session. Don't clear or compact until the tickets exist.

  4. /implementyou start it

    Builds one ticket. Run /clear first so each ticket starts fresh.

    Inside it, tdd writes a failing test first and then the code to pass it, and code-review checks the result.

  5. pragent picks it

    Writes the pull request: what changed, the evidence it works, and how risky the merge is.

  6. /retroyou start it

    Looks back at the session and suggests changes to your setup, not your code: checks to automate, standards to write down. Run it before you clear.

Fixing bugs (Part 1)

  • /triageyou start it

    Moves a bug report from vague to ready for an agent: is it real, can it be reproduced, what's the brief? Only for issues other people raised. Tickets from /to-tickets are already ready.

  • diagnosing-bugsagent picks it

    For hard bugs: get a command that fails on this bug, find the cause, fix it, then add a regression test. Follow with /retro to ask what would have prevented it.

Getting started and getting unstuck

  • /setup-matt-pocock-skillsyou start it

    Run once per repo. Sets up where issues and docs go.

  • /ask-mattyou start it

    Describe your situation and it tells you which skill to use.

  • /wait-whatyou start it

    Re-explains the last answer in plainer words.

  • /handoffyou start it

    Sums up the session so another agent, or tomorrow's you, can pick it up.

  • /to-questionnaireyou start it

    Stuck on a question only someone else can answer? Writes them a short questionnaire.

  • wizardagent picks it

    For steps only you can do, like creating an API key: writes a script that walks you through them.

Bigger work

  • /wayfinderyou start it

    Maps out work too big for one session as a set of decisions to settle one at a time.

  • /implement-specyou start it

    The alternative to /implement per ticket: builds a whole spec on one branch, running several tickets in parallel, then reviews the lot.

  • /improve-codebase-architectureyou start it

    Finds places the code could be simpler, shows them in a report, then grills you on one.

  • prototypeagent picks it

    Builds a throwaway version to answer a design question before committing to it.

Learning

  • /teachyou start it

    Teaches you a topic over several sessions, with short lessons and quizzes.

  • researchagent picks it

    Looks a question up in primary sources and saves the answer with citations.
